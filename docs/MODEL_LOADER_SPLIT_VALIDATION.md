# Split GGUF identity and construction failure cleanup

The shared model loader previously checked the total number of tensors across
shards but ignored the secondary files' declared shard index, split count and
total tensor count. The final regression executable, run against the frozen
old library, accepts a secondary file that declares index zero instead of one
and fails the test. This is a loader defect, independently of model inference.

The loader now checks each secondary file's `split.no` and `split.count` as
UINT16, and `split.tensors.count` as INT32, before publishing its tensor
inventory. Values must agree with the expected filename position and first
shard. Architecture metadata is optional in secondary shards; if repeated, it
must be a matching string. This preserves the format generated by the
[upstream splitter](https://github.com/ggml-org/llama.cpp/blob/master/tools/gguf-split/gguf-split.cpp),
which puts general model metadata only in the first file. Empty first shards
and merged single-file outputs with `split.count=0` remain accepted.

A separate negative control exposed constructor cleanup leaks. Failed
construction does not invoke the object's destructor, so raw GGUF metadata and
GGML tensor contexts were retained. A local construction guard now frees the
published metadata/contexts on failure; temporary shard metadata and tensor
contexts have scoped owners until their inventory is adopted. File objects and
other containers continue to use their existing ownership.

Evidence is frozen under
`/home/xero/Desktop/test/results/ese-loader-split-validation-20261011`:

- `test-model-loader-splits` creates real tiny GGUF files and exercises the
  actual loader, without model weights or architecture promotion. It covers
  37 malformed load attempts and 13 valid constructions, including eight
  repetitions of missing files, truncated headers and truncated payloads,
  each followed by successful loading. Twelve valid split inventories also
  reject a deliberately incorrect secondary tensor shape.
- Final native replay against the old library exits 1 because the malformed
  index is accepted; the candidate exits 0 using the same executable.
- The original strict ASan/UBSan/leak control reports 13,560 bytes leaked in
  272 allocations. Final paired failure-cleanup replay reproduces that leak
  with the old library and reports no sanitizer failure with the candidate.
  That paired replay disables external stack symbolization only: preloading
  the instrumented old library into the external symbolizer caused its
  process to fail. Leak/error detection remains enabled, and the original
  fully symbolized leak report is retained.
- Five normal tests and five strict ASan/UBSan/leak tests pass: split loader,
  Qwen metadata fixture, unsupported GGUF types/alignment, production
  architecture rejection and sequence-output session ownership.
- Read-only real-artifact inventories succeed through the candidate loader:
  Qwen IQ1_M has two files/1,224 tensors; GLM-5.3-Flash Maya-L has four
  files/1,412 tensors. Their secondary shards carry the three split fields
  and omit the optional architecture string. No tensor payload is copied or
  model graph executed by this inspection.

This validates shard declaration consistency and constructor cleanup. It
does not authenticate that same-shaped files come from the same checkpoint,
establish model output correctness, qualify every architecture's metadata or
tensor family. Remaining Qwen loader/shape,
whole-model, resource/failure, long-context and release gates stay open.

Initial failures in the evidence include a lambda enum-name collision during
compilation, a corrected ctypes inspector signature, and the external
symbolizer/preload conflict. They are retained and excluded from passing
qualification. The source model files remain read-only.
