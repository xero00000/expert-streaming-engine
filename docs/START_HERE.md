# Your first local AI conversation

ESE Studio is the desktop app. ESE is the engine that loads and runs the model.
A model is the downloaded AI you will talk to. You choose the model; Studio
helps you find it, launch it and start a conversation.

## 1. Install the right package

Open the [releases page](https://github.com/xero00000/expert-streaming-engine/releases)
and check the version. The v0.2.1 candidate is prepared but unpublished; an
older published release has its own instructions and verified scope.

Follow the [installation guide](install.md) for your system. Linux has separate
CPU and NVIDIA CUDA packages. Windows installers contain both runtimes and can
select the CPU runtime when NVIDIA hardware is unavailable. Physical Windows
GPU inference remains unqualified for the current candidate.

Download the checksum file for the same release and verify your package before
running it. The installation guide includes the exact commands. Model files
are downloaded separately and can be much larger than the app.

## 2. Find a model your PC can try

Open **ESE Studio**. The optional **Help improve ESE** sharing choice starts off;
you can leave it off and continue.

Already have model files? In **Models**, choose **Add model folder** and select
their folder. Otherwise, open **Model hub** to search Hugging Face for GGUF
models and choose a download folder. Use a model whose architecture ESE supports
and begin with a smaller file that fits your available memory.

A **GGUF** is a model file. You may see several versions of one model: a
**quantization** is a version that uses a different amount of memory, which can
also change answer quality. Studio groups these choices and estimates their
memory fit. A recommendation is an estimate, not a speed or quality guarantee.

Keep every part of a split model in the same folder. Leave space for the full
download, temporary files and your normal computer use. If Studio marks a model
**Validation gated**, choose another supported model for your first launch.

[Check what your PC can run →](WHAT_CAN_MY_PC_RUN.md)

## 3. Launch it and say hello

In **Models**, select your model and review **Inspect plan**. The plan shows
how ESE intends to use memory; it does not run a benchmark. Start with a modest
context size — the amount of conversation the model can keep in view — and
increase it after checking that your normal workload runs well.

Choose **Start model** and wait for the server to become ready. Open **Chat**
and send a short prompt, for example:

> Explain how a rainbow forms in three simple sentences.

The answer is generated by the model running on your computer. You can stop a
reply, regenerate it and clear the conversation. The Chat screen keeps its
history on your device.

## Make the next launch easier

Once your first conversation works, explore **Config sweeper**. Its Quick mode
tries real launches and measures candidate settings; it can still take time
with a large model. Review the measured results and save a verified profile
for future launches. A preview describes planned tests, while a verified
result records a completed trial.

For more controls, read the [Studio guide](../studio/README.md). For terminal
commands and APIs, use the [engineering guide](ENGINEERING_GUIDE.md).

## If something gets in the way

| What you see | What to try |
| --- | --- |
| No models in the library | Add the folder containing your GGUF files; check that all download parts are complete |
| A model marked Validation gated | Use a supported model; experimental production gates remain in place |
| Not enough memory | Close other GPU-heavy apps, select a smaller model file or lower context, then inspect the plan again |
| Slow replies | Check model size, available RAM, SSD activity and actual GPU use; streaming trades memory for data movement |
| A package is missing from a release | Check that the instructions match the published version; candidate filenames are not a published download |

Model searches/downloads use Hugging Face and update checks use GitHub. Chat
uses the local ESE endpoint. Any external agent apps you add have their own
network behavior. Benchmark sharing is optional and off by default.
